# proving local

내 PC에서 proving을 실행하고, 사이트와 같은 계정의 공부 기록을 사용하는 앱입니다. 사이트와 동일한 **공부·프로필·기록·탐색·설정 화면**을 제공하며, ChatGPT 플랜을 AI 용도로 연결할 수 있습니다.

- 공부 데이터: [proving 사이트](https://proving.mynameis.life)의 연결한 계정에 저장
- ChatGPT 로그인 정보: 내 PC에만 보관
- 환경변수·DB·Supabase 설정: 사용자 설정 불필요
- 인터넷 연결: 필요

## 1. 준비하기

- [Node.js](https://nodejs.org/) **22.6 이상**과 npm
- [Git](https://git-scm.com/downloads)
- proving 사이트에 로그인할 본인 GitHub 계정
- AI 사용을 위한 본인 ChatGPT 계정 또는 OpenAI API 키

터미널에서 설치 여부를 확인합니다.

```sh
node --version
npm --version
git --version
```

저장소에 접근할 수 없다면 GitHub 로그인 계정과 저장소 접근 권한을 확인하세요. 비공개 저장소는 초대받은 계정만 내려받을 수 있습니다.

## 2. 처음 설치하기

앱을 보관할 폴더에서 터미널을 열고 실행합니다.

```sh
git clone https://github.com/yeaseul7/proving-local.git
cd proving-local
npm ci
```

이후의 모든 명령은 **proving-local 폴더 안에서** 실행합니다. 이 폴더에는 `package.json`과 `package-lock.json`이 있어야 합니다.

## 3. 실행하고 사이트 계정 연결하기

```sh
npm run dev
```

터미널을 켜둔 채 브라우저에서 [http://127.0.0.1:3005](http://127.0.0.1:3005)를 엽니다. `localhost:3005`로 열어도 기본 실행 주소로 자동 이동합니다.

처음 한 번은 이 PC를 사이트 계정에 연결해야 합니다.

1. [proving 사이트](https://proving.mynameis.life)에 본인 GitHub 계정으로 로그인합니다.
2. 사이트의 **설정 → 연결된 기기 → 연결 코드 발급**을 누릅니다.
3. [로컬 앱의 계정 연결 화면](http://127.0.0.1:3005/connect)을 열고 코드를 입력합니다.
4. **이 계정으로 연결**을 누릅니다.

연결 코드는 **10분 동안 한 번만** 사용할 수 있습니다. 새 코드를 발급하면 이전 코드는 무효가 됩니다.

연결 후 사이트에 있던 프로필·기록을 로컬에서도 사용할 수 있습니다. 로컬에서 수정하거나 저장한 데이터도 같은 사이트 계정에 반영됩니다. DB 접속 정보나 운영자의 로그인 정보를 받을 필요가 없습니다.

### 터미널에서 연결하는 방법

화면에서 코드를 입력하는 대신, 서버를 시작하기 전에 다음 명령으로 연결할 수도 있습니다. 두 방법 중 하나만 사용하면 됩니다.

```sh
npm run link -- ABCD-EFGH-JKMN
npm run dev
```

`ABCD-EFGH-JKMN`은 예시이므로 사이트에서 발급받은 코드로 바꾸세요.

## 4. AI 연결하고 공부하기

**사이트 계정 연결과 ChatGPT 로그인은 서로 다른 단계**입니다.

| 연결 | 용도 |
| --- | --- |
| 사이트의 기기 연결 코드 | 프로필·공부 기록을 저장할 proving 계정 선택 |
| 로컬 앱의 ChatGPT 로그인 | 본인 ChatGPT 플랜으로 AI 사용 |

1. 로컬 앱의 **공부 중** 화면을 엽니다.
2. **ChatGPT 플랜으로 시작하기**를 누릅니다.
3. 브라우저에서 본인 ChatGPT 계정으로 로그인하고 플랜 사용을 승인합니다.
4. 로컬 앱으로 돌아오면 모델을 선택해 질문합니다.
5. 공부를 마치고 **기록하기**를 누르면 요약과 원본 대화가 저장됩니다.

사이트에서 **기록**을 열어 같은 공부 노트가 보이는지 확인하면 연결을 검증할 수 있습니다. 실제 AI 사용 가능 여부는 본인 계정·플랜과 OpenAI의 승인 조건에 따릅니다.

OpenAI API 키 방식을 사용하려면 **설정 → GPT API 키 관리**에서 본인 키를 등록한 뒤 공부 화면에서 **GPT**를 선택합니다. 사이트에 이미 등록한 키도 사용할 수 있습니다. API 키는 배포 서버에 암호화되어 저장됩니다.

## 다음부터 실행하기 / 종료하기

처음 연결한 PC에서는 다음 명령만 실행하면 됩니다.

```sh
cd proving-local
npm run dev
```

이미 해당 폴더 안이라면 `cd proving-local`은 생략합니다. 터미널에 표시되는 [로컬 주소](http://127.0.0.1:3005)를 브라우저에서 여세요.

종료하려면 서버를 실행한 터미널에서 **Ctrl+C**를 누릅니다. 터미널을 닫으면 서버도 종료될 수 있습니다.

사이트에서 기기 연결을 해제하거나 로컬 앱에서 로그아웃한 경우에는 새 연결 코드가 필요합니다. ChatGPT 승인이 만료·철회된 경우에도 AI 연결을 다시 진행해야 합니다.

## 새 버전으로 업데이트하기

GitHub에 새 코드가 올라와도 **내 PC의 앱이 저절로 업데이트되지는 않습니다.**

1. 서버를 실행 중이라면 터미널에서 **Ctrl+C**로 종료합니다.
2. proving-local 폴더에서 실행합니다.

```sh
git pull --ff-only
npm ci
npm run dev
```

3. 브라우저를 새로고침합니다.

일반적인 업데이트에는 기기 연결 코드를 다시 발급받을 필요가 없습니다. 페이지 구조가 바뀌었으면 시작 시 오래된 Next 개발 캐시만 자동으로 정리합니다. `.local` 폴더와 브라우저 저장 데이터를 직접 삭제하지 마세요.

ZIP으로 내려받으면 Git 업데이트 명령을 사용할 수 없습니다. 위 업데이트 방법을 사용하려면 처음부터 `git clone`으로 설치하세요.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
| --- | --- |
| `npm` 또는 `node` 명령을 찾을 수 없음 | Node.js 설치 후 터미널을 다시 열고 버전을 확인합니다. |
| `npm ci`에서 lockfile이 없다는 오류 | 현재 폴더에 `package.json`과 `package-lock.json`이 있는지 확인합니다. 저장소를 처음 clone했을 때 파일이 없다면 `main` 브랜치와 최신 코드를 확인합니다. |
| `3005` 포트를 이미 사용 중이라는 오류 | 기존 proving 또는 proving-local 서버의 터미널에서 Ctrl+C로 종료한 뒤 다시 실행합니다. |
| 연결 코드가 만료됐거나 올바르지 않음 | 사이트에서 새 코드를 발급받아 연결합니다. 이미 사용한 코드는 다시 쓸 수 없습니다. |
| 연결 가능한 기기 수 초과 | 설정에서 사용하지 않는 기기의 연결을 해제합니다. 계정당 최대 5대입니다. |
| 사이트에 연결하지 못하거나 기록이 안 보임 | 인터넷·사이트 접속 상태와 연결한 사이트 계정을 확인합니다. 기기가 해제됐다면 새 코드로 연결합니다. |
| 로그인 후에도 AI를 사용할 수 없음 | 공부 화면에서 AI 종류와 모델을 선택했는지, ChatGPT 플랜 사용 승인을 완료했는지 확인합니다. |
| `git pull`이 로컬 변경 때문에 중단됨 | 오류 메시지에 나온 변경 파일을 확인하세요. 수정한 파일을 보관하기 전에 강제로 초기화하지 마세요. |

## 데이터는 어디에 저장되나요?

| 데이터 | 보관 위치 |
| --- | --- |
| 공부 대화·초안·요약·프로필·공개 설정 | 연결한 proving 사이트 계정의 서버 DB |
| ChatGPT 인증 정보 | 이 PC의 `.local/` |
| 사이트 계정에 접근하는 기기 토큰 | 이 PC의 `.local/` |
| 복구용 초안 사본·화면 설정 | 사용 중인 브라우저 |

`.local` 폴더를 다른 사람에게 전달하거나 GitHub에 올리지 마세요. 소스는 공유할 수 있지만 각자 사이트 계정을 만들고 본인 PC에서 연결해야 합니다. 같은 PC에서 다른 계정으로 바꿀 때는 별도 앱 폴더와 브라우저 프로필을 사용하는 편이 안전합니다.

로컬 로그아웃은 이 PC의 기기 연결도 해제합니다. 계정 탈퇴는 사이트에서 진행합니다.

## 이 저장소는 어떻게 업데이트되나요?

이 저장소는 **proving 원본 소스에서 자동 생성되는 사용자 배포본**입니다.

```text
proving에서 공통 코드 수정
  → proving/main에 push
  → GitHub Actions에서 로컬 앱 생성·타입 검사·테스트·빌드·화면 검증
  → 성공하고 생성 결과가 달라졌으면 proving-local/main에 자동 커밋·push
  → 사용자가 자기 PC에서 git pull → npm ci → npm run dev
```

사이트의 Vercel 배포와 사용자용 레포 갱신은 같은 원본 push에서 각각 실행됩니다. **사이트 배포가 완료됐다는 이유만으로 이 저장소 갱신까지 끝난 것은 아닙니다.** 자동 검증이 실패하면 사용자용 레포는 갱신되지 않습니다. 사이트 전용 변경처럼 로컬 생성물에 차이가 없을 때도 새 커밋이 생기지 않습니다.

공통 UI와 기능은 proving에서 수정합니다. 이 저장소의 생성 파일을 직접 수정하면 이후 자동 갱신과 충돌할 수 있습니다. README도 원본의 `local-app/templates/README.md`에서 관리합니다.

## 개발 검증 및 실행 방식

일반 사용자는 설치·연결·실행·업데이트만 진행하면 됩니다. 코드 변경을 검증하려면 다음 명령을 사용합니다.

```sh
npm test
npm run typecheck
npm run build
```

최적화된 버전으로 실행하려면 개발 서버를 종료한 뒤 실행합니다.

```sh
npm run build
npm start
```

기본 주소는 두 실행 방식 모두 `http://127.0.0.1:3005`입니다.
